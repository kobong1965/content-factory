# 语音识别路由深度排查与修复（0.1.42）

## 用户现象

自动剪辑项目 111 在“素材分析”阶段 10% 失败，界面显示“本地与 API 语音识别均不可用”。模型连接页显示已验证的 `gpt-6-sol`，但该连接是图文 Chat Completions 能力；它没有被验证为音频转写服务。

## 根因

1. 本地 ASR 使用 `large-v3-turbo` CPU `int8` 运行时，日志出现 `mkl_malloc: failed to allocate memory`。这是本机内存分配失败，不是视频时长、字幕规则或素材读取失败。
2. 旧网关配置把文本/图片模型标记为 `speech`，而语音任务实际应调用 OpenAI 兼容的 `POST /audio/transcriptions`，两者协议不同。
3. 自动剪辑 worker 原先把视频审核（图文）路由复用给 ASR，导致图文模型被错误地当作语音模型调用。当前配置地址也没有经过真实音频转写探针验证。

## 修复内容

- 语音用途现在强制要求 `audio` 输入能力；只有显式配置的音频模型才能进入 API 备用路由。
- 读取旧配置时只在内存中移除不合法的 `speech` 声明，不改写用户的加密配置文件。
- 自动剪辑 worker 单独读取 `speech` 路由，不再复用 `video_review` 图文模型。
- 本地 ASR 内存不足会显示明确原因，并提示关闭占内存程序、换较小模型或配置真正支持 `/audio/transcriptions` 的 API。
- 版本递增至 0.1.42；保留桌面快捷方式、安装目录、用户数据目录和现有项目记录。

- 前端模型设置与项目错误展示：31 passed；合同测试：17 passed。
- 核心回归：893 passed；桌面行为：30 files / 157 passed；类型检查、Vite 构建和生产资源构建通过。
- 隔离浏览器验收 `E:\Codex工作盘\temp\speech-hardening-042-browser-2`：6 项通过，覆盖项目持久化、新建字段、失败保留输入、三个一级入口、1080p/125%/150% 等效视口、小窗口和 200% 文字放大。
- 原生桌面窗口已通过保留的“爆款内容工厂”快捷方式启动，显示版本 0.1.42，本机服务已连接，当前服务 build id 为 `content-factory-0.1.42`，数据 profile 未改变。

## 当前边界与后续动作

项目 111 的旧失败记录没有被自动付费重试；这是有意保留，避免在语音接口没有真正可用前再次产生费用。当前 0.1.42 的普通“连接并读取模型”流程仍只验证图文/结构化能力，因此不会把普通 GPT/Qwen 模型伪装成语音模型；独立的“语音转写 API（备用）”连接与真实音频探针仍是下一步能力，不能用图文验证代替。要重试该项目，需要先提供一个真实支持 `POST /audio/transcriptions`、能返回词/段时间戳且 API Key 有效的音频模型，再接入该独立路由。

在配置真实音频接口前，项目参数、素材和失败日志都会保留；重新尝试前会再次检查文件可读性。未配置音频 API 时，界面会明确显示“本地与 API 语音识别均不可用”，而不会继续调用错误的图文模型。
