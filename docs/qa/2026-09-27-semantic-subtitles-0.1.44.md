# 语音转写 API 与语义字幕验收（0.1.44）

## 本次目标

自动剪辑成片恢复“主播口播对应字幕”：

- 语音转写模型负责从原始音频返回原话、词级起止时间和置信度。
- 文本模型只负责选择连续词的语义分组边界，不得改写、补词、删词、调序或均分时间。
- 本地由原始词序重新拼接字幕文字，并把原始词时间投影到每条字幕；语义模型返回不完整、重复或乱序边界时直接失败，不生成猜测字幕。
- 视频渲染继续使用原素材音轨；字幕是叠加层，不替换主播原声。

## API 连接行为

模型连接设置新增“连接用途”：

1. 图文模型：视频分析、规划和语义分组。
2. 语音转写模型：`/audio/transcriptions`，必须返回真实 `words` 或 `segments` 时间信息。

语音模型连接会用短 WAV 做接口、鉴权、模型 ID 和 JSON 合同探针；探针只证明接口可用，不冒充真实识别质量。正式成片仍必须收到真实音频的词级时间戳。

中转站地址兼容以下两种形式：

- `https://host/audio/transcriptions`
- `https://host/v1/audio/transcriptions`

当用户填写不带 `/v1` 的基地址时，程序先尝试第一种，收到 404/405 后再尝试第二种；不会把 401、403 或模型错误误判为路径问题。

## 失败保护

- 没有可用语音转写结果时，项目停在前置检查，不进入付费规划或渲染。
- 语音 API 返回没有可用时间戳时，明确报错，不使用随机均分字幕。
- 旧的本地转写/测试数据仍可在没有语音路由时使用；显式配置的语音路由优先于本地 ASR。
- 语义字幕的审校字段（`semantic_reason`、`semantic_confidence`、`alignment_source`）可随字幕草稿保存，人工修改后旧词级对齐会失效并要求重新对齐。

## 用户配置前提

需要先保存一个图文模型，再添加一个明确支持音频转写的模型，并把它连接用途设为“语音转写模型”。语音模型和图文/文本模型可以是同一家中转站，也可以分开；不能把只支持文字或图片的模型当作语音模型。
