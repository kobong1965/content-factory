# 0.1.38 片段重复复用修复与验收

## 用户规则与原因

2026-09-23 用户明确：同一帧/同一片段可以在同一条或不同成片里重复使用，不存在使用一次后消耗掉的限制。

旧 0.1.37 的 `validate_edit_plan` 要求下一段起点不得早于上一段终点，同时模型提示词要求按源时间排序、不重叠。这错误地拒绝了重复选段、源区间部分重叠、倒序选择和 A→B→A。前置检查还把原片短于目标最短成片直接判成不可生成，没有考虑复用。

## 实现范围

- 取消源时间的单调/不重叠校验，保存原始 `clips` 顺序，逐次累计每次使用的时长。
- 模型上下文与开发者提示明确允许同片/跨成片复用，JSON schema 与现有 30 段资源上限一致。
- 原素材可读性、有效起止范围、单成片单原片、款号隔离、目标数量/时长仍严格检查；不把重复区间合并、不自动剪短口播。
- 前后端预检按原片时长乘现有最多 30 段评估是否存在可行长度；这不是帧使用次数限制。
- 历史失败仍保持原状态，UI 明确提示“上次剪辑被旧版重复选段规则拦截”，不把旧失败冒充成功。
- 保留原有渲染/登记检查点、字幕声学对齐和失败后复用有效计划的恢复机制；登记恢复也执行新的只读最终媒体时长检查，不重新调用模型或编码。
- 多段中间音频使用 PCM，按精确毫秒时长建立拼接偏移，最终按源帧率统一视频时间线并进行一次 AAC 编码，防止每段帧取整/AAC 延迟累积。不使用整片尾部 `-t` 或 `-shortest` 强行截断。
- 底片、最终视频、登记恢复三处检查真实时长与计划差异。物理编码容差为整条输出 `max(100 ms, 一帧 + 25 ms)`，不随段数倍增；计划自身仍必须严格符合用户时长设置。
