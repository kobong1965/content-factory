# 原声保留模式与可选 ASR（0.1.43）

## 用户问题

此前自动剪辑在分析阶段和最终渲染阶段都把 ASR 当作硬前置。电脑没有可用本地语音模型、API 中转站只支持文字/图片，或 `/audio/transcriptions` 不可用时，即使用户只想保留原素材口播，也会在 10% 或渲染阶段失败。

音频模型的职责是“听懂口播、生成字幕时间轴、寻找口播自然断句”，不是保存原声音轨。原声音轨由 FFmpeg 的音频映射和最终编码负责保存。

## 修复内容

- 新增字幕模式“仅保留原声 · 不生成字幕”。
- 该模式的规划优先使用本机镜头边界和关键帧，不调用本地 ASR，也不调用语音 API；连续长镜头没有可用镜头边界时，降级为 15—30 秒硬时长窗口，仍然要求图文视频审核模型可用。
- `bounded_15_30` 下使用完整镜头边界组合 15—30 秒片段；连续长镜头则使用固定硬时长窗口，并在方案中保存视觉/固定窗口证据。它不声称口播句子在切点结束，也不会虚构 transcript/words。
- 渲染仍使用原片视频和音频流，跳过最终 ASR，登记空 `.srt` 和空 cues 字幕草稿；成片审核和字幕编辑的合同仍可打开该草稿。
- 清单会明确记录“关闭字幕并跳过 ASR”，不再把原声模式误标为“字幕来自 ASR”。
- 原有普通电影字幕、逐字揭示、重点词高亮和自动混合模式保持不变，仍要求真实音频时间戳；这些模式没有 ASR 时会明确失败并保留项目。

## 使用边界

如果只想保留主播原声：在“新建项目”或失败项目的“修改生成条件”中选择“仅保留原声 · 不生成字幕”，保存后重新尝试。这样不需要语音模型，但切点只承诺画面镜头完整和硬时长范围，不保证一句口播完整。

如果需要电影式整句字幕、逐字出现、重点词高亮，仍选择对应字幕模式，并配置本地 ASR 或真正支持 `POST /audio/transcriptions` 且返回 words/segments 时间戳的语音 API。普通 GPT/Qwen 文字/图片模型不能冒充语音模型。

本轮没有自动重试用户现有失败项目，也没有发起真实付费模型请求；现有项目和素材被完整保留，用户可先修改模式再自行点击重新尝试。
